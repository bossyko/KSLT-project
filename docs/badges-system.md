# Система достижений (бейджей) KSLT

## Обзор

Система автоматически и вручную присваивает бейджи игрокам за достижения. Всего **27 бейджей** — 25 автоматических и 2 ручных.

---

## Где отображаются бейджи

| Место | Что видно |
|-------|-----------|
| **Профиль игрока** (player.html) | Все earned бейджи (яркие) + locked (серые с подсказкой "как получить") |
| **Шапка профиля** | Первые 5 emoji earned бейджей рядом с именем |
| **Рейтинг** (players.html) | До 3 emoji рядом с именем в таблице и на подиуме |
| **Дашборд** | Toast-уведомление при получении нового бейджа |
| **Админка → Игроки → Карточка** | Таблица earned бейджей + ручная выдача + удаление |

---

## Как присваиваются бейджи

### Автоматически (25 бейджей)

Триггер в базе данных срабатывает при обновлении данных игрока (`wins`, `losses`, `form`, `points`). Это происходит когда:

- **Финализируется турнир** — `recalcPlayerPoints()` обновляет wins/losses/points/form → триггер проверяет все условия
- **Админ меняет очки вручную** — points меняется → триггер срабатывает
- **Игрок входит в дашборд** — дополнительная проверка через RPC (раз в час)

### Вручную (2 бейджа + любой другой)

Админ может выдать любой бейдж в карточке игрока:
1. Открыть **Админка → Игроки → выбрать игрока**
2. В секции **"Достижения"** выбрать бейдж из dropdown
3. Нажать **"Выдать бейдж"**

Также можно:
- **Удалить бейдж** — кнопка ✕ в таблице earned бейджей
- **Проверить бейджи** — кнопка запускает автоматическую проверку всех условий (полезно для ретроспективы)

## Техническая часть (для разработчиков)

### Таблицы в Supabase

- **`badge_definitions`** — справочник всех 27 бейджей (id, name, icon, condition_type, condition_value)
- **`player_badges`** — связь игрок↔бейдж (player_id, badge_id, earned_at)

### Ключевые компоненты

- **`check_and_award_badges(player_id)`** — SQL функция, проверяет все условия и выдаёт заслуженные бейджи. Возвращает массив ID новых бейджей.
- **`trigger_check_badges`** — триггер на `players` таблице, вызывает `check_and_award_badges` при изменении wins/losses/form/points.
- **SQL миграция** — `sql/badges-migration.sql`

### Файлы фронтенда

| Файл | Роль |
|------|------|
| `js/player.js` | Загрузка и отображение бейджей в профиле (earned + locked) |
| `js/players.js` | Emoji бейджей в таблице рейтинга |
| `js/dashboard.js` | Toast-уведомление при новом бейдже |

## FAQ

**Q: Бейдж выдался ошибочно. Как убрать?**
A: Админка → Игроки → карточка игрока → секция "Достижения" → кнопка ✕ рядом с бейджем.

**Q: Игрок должен был получить бейдж, но не получил.**
A: Открыть карточку игрока в админке → нажать "Проверить бейджи". Если условие выполнено — бейдж будет выдан автоматически. Если нет — выдать вручную через dropdown.

**Q: Можно ли добавить новый бейдж?**
A: Да, добавить запись в таблицу `badge_definitions` в Supabase Dashboard. Для автоматических бейджей нужно также добавить логику в функцию `check_and_award_badges`.

**Q: Бейджи "Принял вызов" и "Challenger" — когда их выдавать?**
A: Эти бейджи выдаются вручную администратором, когда игрок набрал достаточно принятых/отправленных вызовов на матч.
