# HTTP — Наглядные схемы

## 1. Как работает HTTP (запрос-ответ)

```
  БРАУЗЕР (клиент)                              СЕРВЕР (Supabase)
  ┌─────────────┐                              ┌─────────────────┐
  │             │  ──── REQUEST (запрос) ────>  │                 │
  │  Твой       │                              │   База данных   │
  │  компьютер  │                              │   + API         │
  │             │  <── RESPONSE (ответ) ─────  │                 │
  └─────────────┘                              └─────────────────┘

  Запрос содержит:                             Ответ содержит:
  • URL (куда)                                 • Status Code (200, 404...)
  • Method (GET, POST...)                      • Headers (заголовки)
  • Headers (токен, ключи)                     • Body (данные JSON)
  • Body (данные, если POST)
```

  │   302 Found        — Временный редирект                 │

## 7. HTTP vs HTTPS

```
  HTTP (без шифрования):

  Браузер ─────── "password: 12345" ───────> Сервер
                        │
                     🕵️ Хакер
                  видит: "password: 12345"


  HTTPS (с шифрованием):

  Браузер ─────── "a7$kQ!2xZ#9m..." ──────> Сервер
                        │
                     🕵️ Хакер
                  видит: "a7$kQ!2xZ#9m..."
                  (бесполезный мусор)
```

## 8. TLS Handshake (рукопожатие)

```
  Браузер                                        Сервер
     │                                              │
     │  1. ClientHello                              │
     │  "Хочу безопасное соединение"                │
     ├─────────────────────────────────────────────>│
     │                                              │
     │  2. ServerHello + Сертификат 📜               │
     │  "Вот мой паспорт, я настоящий"              │
     │<─────────────────────────────────────────────┤
     │                                              │
     │  3. Браузер проверяет сертификат ✅            │
     │     Создаёт секретный ключ 🔑                 │
     │     Шифрует его сертификатом сервера          │
     ├─────────────────────────────────────────────>│
     │                                              │
     │  4. Сервер расшифровывает 🔑                   │
     │     Теперь у обоих ОДИНАКОВЫЙ ключ!          │
     │<─────────────────────────────────────────────┤
     │                                              │
     │  ══════════════════════════════════════════  │
     │  Дальше ВСЁ шифруется общим ключом 🔐        │
     │  ══════════════════════════════════════════  │
     │                                              │
     │  { email: "test@mail.com",                   │
     │    password: "mypass" }                       │
     │           ↓ превращается в ↓                 │
     │  "x8Kp$2!qW#nR@7vL..."                      │
     ├─────────────────────────────────────────────>│
     │                      расшифровывает обратно → │
     │                                              │
```

## 10. Два типа шифрования

```
  ┌──────────────────────────────────────────────────────────┐
  │  АСИММЕТРИЧНОЕ (два ключа) — для рукопожатия             │
  │                                                          │
  │  🔓 Публичный ключ — раздаётся всем (в сертификате)      │
  │  🔐 Приватный ключ — только у сервера                    │
  │                                                          │
  │  Зашифровал 🔓 публичным → расшифрует ТОЛЬКО 🔐 приватный │
  │                                                          │
  │  Аналогия: ПОЧТОВЫЙ ЯЩИК                                │
  │  🔓 = щель (любой бросит письмо)                         │
  │  🔐 = ключ от ящика (только хозяин прочитает)            │
  │                                                          │
  │  + Безопасно   - Медленно                                │
  └──────────────────────────────────────────────────────────┘

  ┌──────────────────────────────────────────────────────────┐
  │  СИММЕТРИЧНОЕ (один ключ) — для данных                    │
  │                                                          │
  │  🔑 Один ключ — шифрует И расшифровывает                  │
  │                                                          │
  │  "password:12345" + 🔑 → "x8Kp$2!qW#..."                │
  │  "x8Kp$2!qW#..."  + 🔑 → "password:12345"               │
  │                                                          │
  │  Аналогия: ОДИН ЗАМОК, ДВЕ КОПИИ КЛЮЧА                  │
  │  Закрыл ты → откроет друг тем же ключом                  │
  │                                                          │
  │  + Быстро   - Как передать ключ безопасно?               │
  └──────────────────────────────────────────────────────────┘

  РЕШЕНИЕ: асимметричное ОДИН РАЗ (передать ключ)
           → дальше быстрое симметричное
```

## 11. Полный процесс шифрования HTTPS

```
  Браузер                                         Сервер
     │                                               │
     │  1. Сервер отправляет 🔓 публичный ключ       │
     │<──────────────────────────────────────────────┤
     │                                               │
     │  2. Браузер ГЕНЕРИРУЕТ случайный              │
     │     симметричный ключ: 🔑 "s3cR3tK3y"         │
     │                                               │
     │  3. Шифрует 🔑 публичным ключом 🔓 сервера:    │
     │     🔑 + 🔓 → "mX9$kL2..."                    │
     │                                               │
     │  4. Отправляет зашифрованный ключ             │
     ├──────────────────────────────────────────────>│
     │                                               │
     │     🕵️ Хакер перехватил: "mX9$kL2..."         │
     │     У него нет 🔐 приватного ключа            │
     │     Расшифровать НЕ МОЖЕТ ❌                   │
     │                                               │
     │  5. Сервер расшифровывает 🔐 приватным:        │
     │     "mX9$kL2..." + 🔐 → 🔑 "s3cR3tK3y"       │
     │                                               │
     │  ════════════════════════════════════════════ │
     │  Теперь у ОБОИХ: 🔑 "s3cR3tK3y"               │
     │  ════════════════════════════════════════════ │
     │                                               │
     │  6. Браузер шифрует данные:                   │
     │     "password:12345" + 🔑 → "Qw7#xP..."      │
     ├──────────────────────────────────────────────>│
     │                                               │
     │  7. Сервер расшифровывает ТЕМ ЖЕ 🔑:          │
     │     "Qw7#xP..." + 🔑 → "password:12345" ✅    │
     │                                               │
```

  │────────────────────────────│────────────────────────────│

  │────────────────────────────│────────────────────────────│

## 17. Проблема Rainbow Table и решение SALT

```
  ПРОБЛЕМА — Rainbow Table:

  Хакер заранее посчитал:
  ┌──────────────┬──────────────────────────────┐
  │ "123456"     │ "$2b$10$abc..."              │
  │ "password"   │ "$2b$10$def..."              │
  │ "qwerty"     │ "$2b$10$ghi..."              │
  └──────────────┴──────────────────────────────┘
                                ↕ сравнивает с БД
  Нашёл совпадение → знает пароль! 😱


  РЕШЕНИЕ — SALT (соль):

  Без соли (одинаковые пароли = одинаковые хэши):

  Костя:  "password123"          → "$2b$10$SAME_HASH..."
  Админ:  "password123"          → "$2b$10$SAME_HASH..."  ← одинаково!


  С солью (уникальная соль для каждого):

  Костя:  "password123" + "aB3$kQ"  → "$2b$10$aB3$kQ.Rw5nT..."
  Админ:  "password123" + "xM9#pL"  → "$2b$10$xM9#pL.Jk8vZ..."
                                        ↑ РАЗНЫЕ хэши!

  Rainbow table бесполезна — нужно считать заново для каждой соли
```

## 19. JWT — структура токена

```
  eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJhYmMtMTIzIiwicm9sZSI6ImF1dGgiLCJleHAiOjE3MDl9.kJ9x_7mRpQw2Nv
  │________________________│.│_____________________________________________________│.│__________________│
          HEADER                              PAYLOAD                                    SIGNATURE
        (алгоритм)                    (данные пользователя)                         (подпись SECRET_KEY)


  Декодируем (Base64 → JSON):

  ┌─────────── HEADER ───────────┐
  │ {                            │
  │   "alg": "HS256",           │  ← алгоритм подписи
  │   "typ": "JWT"              │  ← тип токена
  │ }                            │
  └──────────────────────────────┘

  ┌─────────── PAYLOAD ──────────┐
  │ {                            │
  │   "iss": "supabase",        │  ← кто выдал (issuer)
  │   "sub": "abc-123-user-id", │  ← ID пользователя (subject)
  │   "role": "authenticated",  │  ← роль
  │   "email": "kostya@mail.com"│  ← email
  │   "exp": 1709234567         │  ← истекает (unix timestamp)
  │ }                            │
  └──────────────────────────────┘

  ┌─────────── SIGNATURE ────────┐
  │                              │
  │  HMACSHA256(                 │
  │    header + "." + payload,   │
  │    SECRET_KEY  ← только      │
  │                  у сервера!  │
  │  )                           │
  │                              │
  └──────────────────────────────┘
```

## 20. JWT — процесс логина и проверки

```
  Браузер                                         Сервер
     │                                               │
     │  POST /auth/login                             │
     │  { email: "kostya@mail.com",                  │
     │    password: "mypass123" }                     │
     ├──────────────────────────────────────────────>│
     │                                               │
     │                          1. Хэширует пароль   │
     │                          2. Сравнивает с БД ✅ │
     │                          3. Собирает JWT:     │
     │                                               │
     │                          Header: {"alg":"HS256"}
     │                              +                │
     │                          Payload: {"sub":"abc-123",
     │                            "role":"authenticated",
     │                            "exp": 1709234567} │
     │                              +                │
     │                          Подпись SECRET_KEY 🔐│
     │                              =                │
     │                          eyJhbG...eyJzdW...kJ9│
     │                                               │
     │  { "access_token": "eyJhbG..." }              │
     │<──────────────────────────────────────────────┤
     │                                               │
     │  Браузер сохраняет в localStorage             │
     │                                               │
     │  ═══════════════════════════════════════════  │
     │                                               │
     │  GET /tournaments                             │
     │  Authorization: Bearer eyJhbG...              │
     ├──────────────────────────────────────────────>│
     │                                               │
     │                   Сервер ПРОВЕРЯЕТ:           │
     │                   1. Берёт header + payload   │
     │                   2. Подписывает SECRET_KEY   │
     │                   3. Сравнивает с signature   │
     │                      СОВПАЛО ✅ → настоящий   │
     │                   4. Читает payload:          │
     │                      sub = "abc-123"          │
     │                      role = "authenticated"   │
     │                      exp > now ✅ не истёк     │
     │                                               │
     │  200 OK [{ tournaments data... }]             │
     │<──────────────────────────────────────────────┤
```

## 21. Почему JWT нельзя подделать?

```
  ┌───────────────────────────────────────────────────────────┐
  │                                                           │
  │  Хакер перехватил токен и хочет стать админом:            │
  │                                                           │
  │  Payload (Base64 — легко прочитать и изменить):           │
  │  { "role": "authenticated" }  →  { "role": "admin" }     │
  │                                         ↑                │
  │                                   изменил роль           │
  │                                                           │
  │  НО! Signature = HMAC(header + payload, SECRET_KEY)       │
  │                                         │                │
  │                              Хакер НЕ ЗНАЕТ ❌            │
  │                              SECRET_KEY хранится          │
  │                              ТОЛЬКО на сервере            │
  │                                                           │
  │  Хакер отправляет поддельный токен                        │
  │  Сервер: пересчитывает подпись с SECRET_KEY               │
  │          → НЕ совпадает с signature в токене              │
  │          → 401 Unauthorized ❌ ПОДДЕЛКА!                   │
  │                                                           │
  └───────────────────────────────────────────────────────────┘
```

     │  Authorization: Bearer eyJ...  ← вручную │

     │  это за нас автоматически                │
